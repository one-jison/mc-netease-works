  第九次修改  昼夜只交替一次：四秒里白天一路走到黑夜（半轮 12000 帧），
              走完立刻跳回按下去那一刻的时间
  第十次修改  顺序反过来：按下先把天砸到午夜（全黑），再用四秒一路走到白天，
              一次交替就结束；结束时仍把时间放回按下去那一刻
              （起夜的时间点写在 DAY_NIGHT_START，默认 18000 = 午夜）
  第十一次修改  修好「拿 TNT 把房子炸了，马上按回溯却修不回来」这个 bug。
              原因是爆炸那条路把方块坐标排进队列、过几个 tick 才去读它们
              原来的样子 —— 轮到读的时候那格早成空气了，记下来的是空气，
              所以回溯等于什么都没恢复。现在改成在爆炸事件里【当场】就读
              （爆炸事件是在方块被炸掉之前触发的，这一刻方块还立着），
              炸多少记多少；万一某个版本没给方块列表，还会围着爆点扫一圈兜底。
  第十二次修改  修好「玩家自己没退回五秒前的位置」：
              1) 回溯窗口改成从【按下按钮那一刻】往前推五秒
                 （以前从“真正回溯那一刻”算，那一秒转钟延迟把窗口吃掉了），
              2) 玩家自己的位置一直在记（不再只在身上有药水时记），
                 刚喝完药水马上按也能退回五秒前站的地方，
              3) 找“那时候的样子”改成挑离目标最近的一笔，
                 记录断档时不会一把跳回二十几秒前，
              4) 拉回玩家后用 /tp 兜底核对一次，没到位就补一次。
  第十三次修改  掉落物 / 经验 / 背包 / 经验值 / 箭矢也一起回溯：
              1) 这五秒里才掉出来的东西（方块掉落物、生物掉的经验球）
                 跟着一起清掉；五秒前就在的东西按老规矩退回原位，
              2) 这五秒里捡进背包的东西收回去（只做减法，不往背包里加，
                 免得“放进箱子的东西”又变一份回来变成刷物品），
              3) 这五秒里涨的经验扣回去，
              4) 射出去的箭退回到五秒前的位置。
  第十四次修改  回溯窗口从五秒改成【十秒】，三处跟着变：
              1) 退回时长默认十秒（REWIND_SECONDS = 10.0），
              2) 玩家自己的【血量】也一起退回十秒前的数值
                 （REWIND_SELF_HP 改成默认开），
              3) 箭矢不再“退回到十秒前的位置”，改成【回膛再飞】——
                 放回你弓旁边那个出膛点、速度不动，引擎接着让它
                 照原方向再飞一次（PROJECTILE_FLY_AGAIN = True）。
              箭的【速度】也一起记下来、回溯时写回去（PROJECTILE_KEEP_SPEED）：
              只挪位置的话，已经插进墙里、速度归零的箭会停在半空，
              给回速度才会真的再飞一次。速度用 CreateActorMotion 组件
              （GetMotion / SetMotion）读写；生成那一帧读不到就下一 tick 补读。
              另外顺手修掉一个隐患：数箭的时候会临时借用 pos 这个变量，
              把“玩家自己的位置”覆盖掉，后面的“复活死掉的生物”就会
              拿箭的位置当中心去找，现在改用单独的变量，不再互相干扰。
  第十五次修改  新增【静止药水】（屏右侧的静止按钮）：
              1) 合成：玻璃瓶 ×1 + 时钟 ×1 + 蓝冰 ×2 = 静止 ×1；
              2) 喝下后屏幕右侧出现「静止」按钮，药效三分钟；
              3) 按一下把身边 100 格停住——生物屏蔽原生 AI（顺带冻住动作，
                 官方说明：屏蔽后无法行动、不受重力、不会被推动），
                 箭矢这类抛射物每 tick 把速度按成 0 停在半空（解冻时
                 把原来的速度还回去，接着飞），火焰用 dofiretick 规则
                 关掉，不蔓延也不熄灭；
              4) 再按一下全部恢复，三分钟内可以反复开关；
              5) 电脑端快捷键 G（可在 设置 → 按键 里改，键名 TimeRewindFreeze）；
              6) 掉线 / 死亡 / 药效到点都会自动全部解冻，不会把世界留在
                 “停住”状态。
              打包：本包（已被第十六次修改取代，用下面那个）
  第十六次修改  1) 屏幕【右上角】加了一个跟原版药水效果一样的倒计时方框：
                  静止药水生效时显示，方框里是静止药水的图标，
                  图标下面是剩余时间（3:00 → 2:59 → …），一秒一跳，
                  药效没了自动收掉。
                  做法上服务端只说一次“还剩几秒”，之后由客户端自己往前推，
                  不占带宽，数字也不会卡住。
               2) 每按一下静止按钮，屏幕正中弹一句提示：
                  「静止 · 开启」或「静止 · 解除」，底下带上药效还剩多久，
                  两秒后自己收掉（时间写在 FREEZE_POPUP_SECONDS）。
                  身上没药水时按下去依旧一点反应都没有。
               3) 修掉「箭矢被静止之后还会自己拐个弯」这个 bug。
                  根因：光把速度按成 0 挡不住引擎——它每 tick 还会算重力、
                  还会按速度改朝向，箭就会慢慢往下垂、往一边拐。
                  现在冻住的时候把【速度 + 位置 + 朝向】三样一起记下来，
                  每 tick 一起按住（新函数 _pinProjectile），
                  解冻时只把当初的速度还回去。箭是真的钉在半空了。
               打包：本包（已被第十七次修改取代）
  第十七次修改  1) 右上角那个倒计时方框改小了：图标从 30×30 缩到 16×16
                  （和物品贴图原尺寸一致，最清晰），方框跟着收到 26×36，
                  整体大小跟原版药水效果那个图标一个量级，不再挡视野。
               2) 彻底修好「箭矢被静止之后还会自己拐个弯」。
                  上一次改动（第十六次）猜错了原因：以为只要把位置钉住就行。
                  真正的原因是【箭的朝向是引擎按「这一 tick 的位移方向」算出来的】——
                  速度一旦设成 0，位移方向就只剩重力那个朝下的分量，
                  引擎就把箭掰成头朝下（或者在没有位移时归到 0 度），
                  看起来就是「冻住了还在自己拐弯」。
                  现在的做法：给一个方向正好是箭头原本朝向、但小到几乎不动的速度
                  （FREEZE_HOLD_STEP，默认 0.3 格），让引擎算出来的朝向仍然是原来的；
                  同时把脚底位置先往回让出这一小步，引擎推完正好停在原地。
                  因为每 tick 都重新设一次速度，重力永远攒不起来，
                  所以「朝下」这件事从根上就不会再发生。
                  复现测试跑了 20 秒：位置偏离 0.0000 格、朝向偏离 0.000 度。
               打包：本包（已被第十八次修改取代）

              包里 4 个 UUID（行为包头 / 行为包模块 / 资源包头 / 资源包模块）
              和工程 ID 全部重新生成，都跟盘上已有的任何 ID 不重复；

              照着它换回去就行。
              版本号跟着抬到 1.0.19（上传要求版本往上走）。
              打包：时间回溯_上传包_第二十次修改_新UUID.zip
                    （已另存一份到 文档\临时上传 里）
  第二十次修改  静止期间，点着的 TNT 不再一闪一闪。
              原因：点着的 TNT 自带闪白动画（快炸的时候越闪越急），
              那是引擎跟着引信播的，没有任何接口能停；之前靠“每 2 秒换一坨
              新的 TNT”，反而每换一次就重播一次闪。
              现在的做法：静止期间把点着的 TNT 直接【换成一格真正的 TNT 方块】——
              外形几乎一样，但方块不会闪、不会冒烟、也没有引信，看上去就是
              彻底定住了。解除静止（换开关、走远、药效到点、掉线、死亡）时，
              再把方块撤掉、原地放回一坨点着的 TNT，让它接着炸。
              细节：先放方块、读回来确认真的是 TNT 方块，才删掉点着的那坨
              （同一 tick 内完成，画面上不会闪空）；那格要是被别的东西占着、
              或者放不进去（区域没加载 / 被保护），就走回老办法（把它按住）。
              方块被玩家先挖掉的话就不还了，也不会凭空多冒出一坨 TNT。
              开关：FREEZE_TNT_AS_BLOCK（默认开；关掉就退回第十九次修改那套）。
              打包：本包（已被第二十一次修改取代）
  第十九次修改  静止药水：TNT 也一并停住，炸不起来了
              （之前冻住了、位置钉住了，但引信照走，还是会炸）。
              难点：游戏的引信（TNT 头顶那个倒计时）没有任何接口能按暂停，
              文档里搜“引信 / fuse”是零结果，写 NBT 的接口也没有。
              所以走两条路：
              1) 主路：被冻住的 TNT，每到 FREEZE_TNT_REFRESH_TICKS
                 （默认 40 tick = 2 秒）就在原地【换成一坨刚刚点着的新 TNT】——
                 先造新的、造出来了再删旧的；新的一坨引信是满的（4 秒），
                 于是永远走不到爆炸那一步，看起来就是卡在半空一直不炸。
              2) 兜底：万一真炸了（比如刚点着就冻住、剩的引信实在太短来不及换），
                 在爆炸事件里把这一炸的方块列表每一项的 cancel 位都设成 True
                 （一格都不炸），再让要受伤的对象【临时免疫一瞬间】，
                 顺便把他们的血记下来、过 0.08 秒核对一遍，少了就补回去。
              被冻住的爆炸物按“爆点 + 造它的那个 id”双重认领，
              所以 TNT 是谁点燃的都不会认错。
              苦力怕不需要换（它的 AI 被屏蔽之后就不会自爆了）；
              临时免疫是写进存档的属性，掉线 / 死亡 / 到点都会立刻撤回，
              不会把谁变成永久无敌。
              打包：本包（已被第二十次修改取代）
  第十八次修改  重新修了一遍「箭矢被冻住之后自己动」。
              上一次（第十七次）里我为了把位置钉住，是「先把箭往回退一小步，
              等引擎推回来」，那一退会被画面渲染出来 —— 看起来就是箭在原地
              抖 / 绕圈。这次改成：
              1) 位置只做一件事：每 tick 直接摆回冻住那一格。
                 绝不往回退，所以画面上不会来回弹、不会抖。
              2) 速度只留一点点（FREEZE_HOLD_STEP，默认 0.01 格），
                 方向就是箭头原本的朝向 —— 这样引擎算出来的朝向还是原来的，
                 而这 0.01 格的位移每 tick 都被第 1 步抹掉。
              3) 引擎自己额外推的那一份（重力之类）不靠猜：直接量。
                 上一 tick 它把箭推到哪，减去我们上 tick 给的速度，
                 剩下的就是它干的，这一次从速度里减掉。
                 所以不管引擎是「先加重力再走」还是「先走再加重力」，都对得上。
              跑了两套引擎模型的 30 秒模拟：位置偏离 0.0075 格、
              朝向偏离 0.000 度、回推 0.0000（不会抖）。
               打包：本包（已被第十九次修改取代）

【二、怎么在 MC Studio 里测试】
  1. 打开 MC Studio → 新建/导入：把「时间回溯_上传包_第十八次修改.zip」当组件包导入。
  2. 进游戏后先在工作台合成一瓶「回溯」：
        玻璃瓶 ×1 + 时钟 ×1 + 末影珍珠 ×1 + 红石 ×2
  3. 拿在手里点一下喝掉 → 屏幕左侧出现【回溯】按钮
  4. 按一下（电脑端按键盘上的 R 键，想改键就去 设置 → 按键 里找
     【TimeRewindUse】），看昼夜是否飞快交替、
     身边的羊 / 方块是否退回十秒前、你自己的血是否也回到十秒前的数值。

【三、上传网易开发者平台】
  1. 用【导出】生成 zip（千万不要点【导出（含编辑信息）】，会报错误码 18）。
  2. 更新作品时先把版本号 +1（作品 → 更多 → 配置 → 全部升级），
     否则报错误码 42。
  3. 本包已经过「模组上传前自查」，结论：没有拦路的问题，可以上传。

【五、它是怎么实现的（给后续改代码看的）】
  · 自己：_nearby 返回的列表里不含玩家自己，所以 _sample 里额外给自己推一笔
    （位置 / 朝向 / 血量）。回溯时如果 REWIND_SELF 开着，就把自己也
    SetFootPos 回去；REWIND_SELF_HP 默认开，也就是位置和血量一起回十秒前。
  · 身边一百格内的实体：每 0.5 秒记一笔（位置 / 朝向 / 血量），
    只留最近 30 秒的记录。
  · 方块：在「方块要变之前」把它原来的样子记下来
      - 玩家挖方块  ServerPlayerTryDestroyBlockEvent
      - 生物放方块  ServerEntityTryPlaceBlockEvent
      - 爆炸        ExplosionServerEvent（爆炸是在“方块被炸掉之前”触发的，
                    所以当场就把每格的原样读下来，炸多少记多少；
                    万一拿不到方块列表，就围着爆点扫 EXPLODE_SCAN_RADIUS 格兜底）
    同一格只保留最靠近回溯窗口起点的那一份。
  · 生物死亡：记下类型、位置、维度；回溯时用 CreateEngineEntityByTypeStr
    在它十秒前待着的位置把它重新生出来。
  · 一瓶一次：OnUseButton 里通过冷却检查后立刻调用 _consume(玩家)：
    清掉 _has / _until / _hp / _reviveHp 这些“药水状态”，并发
    EventState{show:0} 让按钮收掉。注意 _spin / _pending 故意不清，
    否则正在转的昼夜和那一秒后的回溯会被自己取消掉；
    _hist / _blocks / _deaths 也留着，回溯要用。
    客户端收到 show=0 时只收按钮，不打断转钟动画（动画自己 1 秒后收）。
  · 打包是白名单：只有 studio.json、work.mcscfg 和两个包文件夹进 zip，
    放在工程根目录的其它东西（比如那个 mp4）不会被带进去，
    免得触发错误码 24。
  · 按下那一声：音频是从「时间回溯」文件夹里那个 mp4 抽出来的，
    用 imageio_ffmpeg 转成 ogg（44100Hz 单声道），放进资源包
    sounds/timerewind/rewind.ogg，再在 sounds/sound_definitions.json 里
    登记成 timerewind.rewind。播放有两条路，先走第一条：
      1) 客户端按下的一瞬间 CreateCustomAudio(玩家/levelId).PlayCustomMusic
         （本地放，零延迟，最跟手）
      2) 万一本机放不出来，客户端 NotifyToServer(EventSound)，
         服务端用 /playsound timerewind.rewind 兜底
  · 昼夜转完回原时间：按下时把（维度、当时的时间）记在 _spinFrom 里，
    转满四秒后 SetTimeOfDay 回那个值；中途死了 / 退出世界也会先放回原时间。
    帧数是算出来的：DAY_NIGHT_ONCE 为 True 时走半轮（12000 帧），
    12000 / (4 秒 × 20 tick) = 150 帧/tick；改成 False 就是 24000/80 = 300。
    按下那一刻还会先 SetTimeOfDay(DAY_NIGHT_START)（默认 18000 = 午夜），
    所以看起来是“一下就黑透了，再慢慢亮起来”。
  · 按下后的节奏：按下 → 服务端立刻开始推昼夜，同时客户端自己放转钟动画；
    REWIND_DELAY（默认 1 秒）之后服务端才真正回溯实体与方块 / 复活生物 /
    响音效 / 发提示。这段延迟写在 TimeRewindConfig.REWIND_DELAY 里。
  · 转钟动画：没有用引擎的旋转接口，而是画了 8 张时钟贴图
    （clock_0..7，指针每张差 45 度），靠切图做出转动效果 ——
    这样任何版本、任何机型都稳，只用最基础的 SetVisible。
    帧数写死在 timeRewindHudScreen.mFrameCount，和贴图数量对应。
  · 动画为什么第一次不卡了：这 8 张贴图是第一次显示时才真正加载进显存的，
    第一次放动画就会卡一下。所以现在开局（HUD 建好后的第一秒）会先
    “热身”一轮：把面板显示出来、透明度调到 0.02（肉眼看不见），
    把 8 帧轮着渲染一遍，贴图和文字就都加载好了，之后再放就顺。
    开关在 timeRewindConfig.ANIM_WARM_UP。
  · 爆炸为什么要“当场读”：ExplosionServerEvent 是在方块被炸掉【之前】触发的
    （官方文档里 blocks 每项第 4 位的 cancel 设成 True 就能取消那一格被炸），
    所以事件里那一刻方块还立着，GetBlockNew 读到的就是爆炸前的样子。
    老写法是把这个坐标排进 _blockQ、每 tick 慢慢读 —— 事件返回后方块立刻被炸掉，
    读到的是 air，_putBlock 再把 air 写回去，等于没恢复（房子修不回来的根因）。
    现在 _blockQ / _drainBlocks 整条路径已经删掉，只在事件里同步读。
   · 回溯窗口是从【按下按钮那一刻】往前推 REWIND_SECONDS 秒，不是从“真正
     开始回溯那一刻”（按下后要等 REWIND_DELAY 秒把转钟动画放完）。
     原来按后者算，这一秒延迟会从十秒里吃掉一秒，看起来就是“只回到
     四秒前”，爆炸只要稍微早一点按就一点都修不回来。
   · 玩家自己的位置一直在记（每 0.5 秒一笔，一个人一次读取，几乎不花性能），
     不再只在“身上有药水”时才记：这样刚喝完药水马上按按钮，
     也一定能退回按下那一刻十秒前站的地方。身边生物的位置还是只在
     有药水时记，省性能。
   · 挑“那时候的样子”用的是“离目标时刻最近的一笔”，不是“不晚于目标的最后
     一笔”：记录万一断档（生物跑出范围又跑回来），后者会一把跳回
     二十几秒前的位置，看起来就像瞬移到莫名其妙的地方。
   · 拉玩家回来的兜底：SetFootPos 之后过 SELF_CHECK_TICKS（默认 5）个 tick
     核对一次，玩家还没到位就用一次 /tp 补上（文档里两个接口都是
     “等同 tp 命令”的语义，这里防的是个别机型上设完又被客户端拉回去）。
   · 按一次按钮后的聊天提示会带上「本轮爆炸 N 次、记下 M 格」（排错用）：
     N > 0 但 M = 0，说明爆炸事件来了、可读到的是空气。
   · 掉落物 / 经验球：实体记录里“最早的那一笔”都晚于 target（＝十秒前它还
     不存在），就说明它是这十秒里才冒出来的，直接 DestroyEntity 清掉；
     十秒前就有的照旧退回原位。
   · 防误清：判断“是不是新的”要先确认记录确实覆盖到了 target
     （_trackFrom 早于 target）。不然刚进世界、或者刚走到一堆老掉落物跟前，
     会把一堆老东西当成新的清掉。
   · 掉落物 / 经验球是一直跟着记的（不像身边生物那样只在有药水时记），
     否则刚喝完药水就按按钮，会判不出来哪些是新的。
   · 背包 / 经验值：每 0.5 秒快照一笔（GetPlayerAllItems / GetPlayerTotalExp），
     回溯时挑“离 target 最近的一笔”，把多出来的部分收回去：
       - 背包：按（物品名 + aux + NBT）统计老快照里每样东西各有多少，
         遍历当前背包，多出来的用 SetInvItemNum 减掉（置 0 = 清空那一格）。
         只减不加：整包还原会把“这十秒里放进箱子 / 丢出去的东西”再变一份
         回到背包里，等于刷物品。
       - 经验：当前总经验比十秒前多的话，SetPlayerTotalExp 写回旧值。
   · 箭矢 / 抛射物：单独一条路，跟别的实体不一样。
     - 十秒前就在飞的老箭：按老规矩退回它十秒前的位置。
     - 这十秒里刚射出去的：不收回、也不销毁，放回【出膛点】再飞一次。
       出膛点靠监听 SpawnProjectileServerEvent 拿（官方文档里这个事件的
       参数是 projectileId / projectileIdentifier / spawnerId；没有发射者时
       spawnerId 是 -1）。优先用发射者脚下往上抬 1.4 格（大约手上那个高度），
       拿不到发射者就退而求其次读抛射物自己的位置。
       先 SetFootPos 放回出膛点，再用 SetMotion 把当初那一箭的速度写回去，
       所以引擎会接着让它往前飞，看起来就是“这一箭重新射了一遍”。
       （速度组件：serverApi.GetEngineCompFactory().CreateActorMotion(id)，
         接口是 GetMotion / SetMotion，服务端对非玩家生物可用。）
     - 出膛点没记到（比如药水是在箭射出去之后才喝的）就退回最早那一笔。
   · 玩家血量：还原玩家时按 REWIND_SELF_HP 决定要不要一起把血写回去，
     血量记录跟着实体采样一起走（每 0.5 秒一笔）。
   · 静止药水（右侧那颗按钮）
     - 开关状态：_fz 记“药效到什么时候”，_fzOn 记“现在把周围停住的玩家”。
       _freezeTick 每 tick 干三件事：药效到点就收按钮、算出该停哪些实体、
       把跑出范围的解冻。
     - 生物：CreateControlAi(id).SetBlockControlAi(False, freezeAnim)。
       官方文档写得很直白——“是否保留AI，False为屏蔽”，freezeAnim 是
       “屏蔽AI时是否冻结动作，仅当 isBlock 为 False 时生效”；
       备注里还有一句关键的话：屏蔽 AI 后的生物无法行动、不受重力、
       不会被推动，但是可以受到伤害、也能被玩家交互，对玩家无效。
       所以生物只要屏蔽一次就行，不用每 tick 去按速度，省性能。
     - 抛射物（箭 / 雪球 / 火球 / 点燃的TNT…）：AI 那套对它们没用，
       只能每 tick 用 ActorMotion 组件的 SetMotion((0,0,0)) 按住；
       冻住之前把 GetMotion() 读到的速度存进 _fzHold，解冻时写回去，
       所以箭是“接着飞”而不是“重新射一遍”。
       新射出去的箭靠 SpawnProjectileServerEvent 当场冻，不用等下一次
       范围扫描（扫描间隔默认 5 tick，等扫描的话箭已经飞出去好几格了）。
     - 火焰：/gamerule dofiretick false —— 火不蔓延、不熄灭，
       解除静止时再 /gamerule dofiretick true 放回去（开关 FREEZE_FIRE）。
       玩家在静止期间想徒手扑灭火，ExtinguishFireServerEvent 里会
       把那一格 fire 重新放回去。
       火苗左右摇晃是引擎自己播的 flipbook 贴图动画，ModAPI 没有
       暂停单格纹理动画的接口（文档里连 flipbook 这个词都搜不到），
       所以“火苗完全静止不动”做不到，“停止燃烧 / 保持火焰”是做到的。
     - 范围：_freezeNear 复用了 _nearby 那套范围查询，但缓存间隔更短
       （FREEZE_RESCAN_TICKS，默认 5 tick），并且和 _nearby 共用抽出来的
       _nearbyRaw，两份缓存互不干扰。
     - 不会把世界留在“停住”状态：掉线、死亡、药效到点、总开关关掉，
       都会走 _freezeReleaseAll：把 _fzAi 里的生物逐个放开、_fzHold 里的
       速度还回去、火焰规则恢复。所有玩家都不在静止状态时也会自动收尾。
       另外每 tick 都会检查“已经不在范围内”的实体并解冻，所以你走远了，
       原来停住的那批会自己恢复。

   · 右上角那个倒计时（第十六次修改加的）
     - 服务端 _fzState(玩家, show, on) 除了 show / on，还多带一个 left
       （= 药效到点的时间减现在，保留一位小数）。所有发给客户端的
       EventFreezeState 都走这个函数，所以喝药、开关、到期三种状态
       都会带上准确的剩余时间。
     - 客户端不靠消息刷新数字：OnFreezeState 里把 left 记成
       _fzLeft / _fzLeftAt，之后 _fzLeftNow() = _fzLeft - 已经过去的时间，
       每 tick 取一次整数秒，变了才去改界面（SetFreezeTimer）。
       这样服务端一秒不发消息，数字照样一秒一跳，也不怕消息丢。
     - 界面那头 TimeRewindHudScreen.SetFreezeTimer(秒) 把它格式化成
       "分:秒" 再写进 label：ctrl.asLabel().SetText(text)。
       （官方文档：LabelUIControl.SetText(text, syncSize=False)，
         路径 mod.client.ui.controls.labelUIControl.LabelUIControl。）
     - 药效没了（show=0）客户端立刻把方框和提示一起收掉，不等下一个 tick。
   · 按按钮弹的那句提示
     - 客户端 OnFreezeButton 里本地先把 _fzOn 翻过来（按钮立刻变色），
       顺手调 _popFreezeTip(新的开关)，标题取 FREEZE_POPUP_ON_TITLE /
       FREEZE_POPUP_OFF_TITLE，副标题后面拼上「（药效剩余 x:xx）」。
     - 停留时长交给客户端 tick 管（_tipUntil 记到点的时间，
       到点调 HideFreezeTip），界面脚本自己不计时，更稳。
   · 箭矢“静止了还拐弯”的根因与修法
     - 只 SetMotion((0,0,0)) 是不够的：引擎每 tick 还会对抛射物算重力、
       并按速度改朝向，所以箭会慢慢下垂 / 偏航，看起来就是自己拐弯。
     - 现在 _freezeEntity 里对抛射物记的是三元组
       （速度, 位置, 朝向）；_freezeTick 每 tick 调 _pinProjectile，
       把 SetFootPos(原位置) + SetRot(原朝向) + SetMotion(0,0,0)
       三样一起按回去。解冻时 _thawEntity 只把三元组里的速度还回去
       （位置和朝向本来就停在原地，不用还原）。

   · 为什么“把箭的速度设成 0”会拐弯（第十七次修改的真正修法）
     - 引擎每 tick 都会按【这一 tick 的位移方向】重算箭的朝向 ——
       射出去的箭一直朝着飞的方向，就是这么来的。
     - 速度设成 0 之后，位移里只剩重力那个向下的分量，
       于是引擎把箭的朝向算成了“朝下”（位移正好是 0 时会被算成
       左右 0 度 / 上下 0 度，也就是归到一个固定方向）。
       脚本就算每 tick 用 SetRot 掰回来，也只是一直在跟引擎抢，
       玩家看到的就是箭慢慢歪掉 / 拐弯。
     - 正确解法（_pinProjectile）：
         速度 = 由“冻结那一刻的朝向”算出来的单位向量 × FREEZE_HOLD_STEP
         位置 = 原本站着的那一格 − 上面这个速度
       引擎推完之后：位置正好回到原处，而算朝向用的方向仍然是
       箭头原本的朝向，所以箭既不动、也不歪。
       因为每 tick 都重设速度，重力攒不起来，也就不存在“朝下”了。
     - 朝向 → 方向向量（_dirOf）：
         dx = -sin(yaw)·cos(pitch)
         dy = -sin(pitch)
         dz =  cos(yaw)·cos(pitch)
       （游戏里 0 度朝正南 +Z，上下角度为正表示朝下）
     - FREEZE_HOLD_STEP 调大：方向更稳，但引擎那一步跨得远，
       贴着墙时更容易被判成撞墙；调小：更贴墙，但更容易被重力带歪一点。
       默认 0.3。另外解冻时（_thawEntity）会把位置、朝向、速度
       三样一起摆回冻结那一刻，接着飞。

   · 抛射物冻结的最终做法（第十八次修改）
     - 三个动作，顺序固定：
         1. SetMotion(我们算出来的速度)
         2. SetFootPos(冻住那一格)      ← 直接摆回去，绝不往回退
         3. SetRot(冻住那一刻的朝向)
     - 为什么不能「往回退一步等引擎推回来」：
       脚本设的中间位置会被客户端渲染出来，玩家看到的就是箭在原地
       来回弹 —— 也就是「抖 / 绕圈」。
     - 速度怎么算：
         want  = 由冻住那一刻的朝向算出的单位向量 × FREEZE_HOLD_STEP
         extra = 引擎自己额外推的那一份（量出来的）
         mv    = want - extra
       量 extra 的办法：上一 tick 引擎把箭推到了 P_now，
       我们上 tick 设的速度是 prev，那么
         extra = P_now - 冻住那一格 - prev
       因为「冻住那一格 + prev + extra」才是引擎推完的结果。
     - 为什么这么写放之四海皆准：
         · 引擎如果「先加重力再走」，它算朝向用的是 mv + extra = want；
         · 引擎如果「先走再加重力」，它算朝向用的是 mv，而这时
           extra 量出来是 0，mv 就等于 want。
         两种都落到 want 上，所以朝向永远是对的。
     - 第一次还没有 extra 可量，先按 FREEZE_HOLD_GRAVITY（默认 0.05）猜一下，
       下一个 tick 就量到真值并立刻改过来（最多错一帧 = 50 毫秒）。
     - 清场：解冻、范围外、掉线、死亡、药效到点都会把 _fzPrev 一起清掉，
       不会留垃圾。

   · 静止期间「点着的 TNT 不闪了」是怎么做的（第二十次修改）
     - 先说为什么之前会闪：点着的 TNT 那个白光是引擎的 flash 动画，跟着引信走
       （越接近爆炸闪得越急），没有接口能停。而第十九次修改是“每 2 秒换一坨
       新的 TNT”，每换一次新的一坨就重新开始闪 —— 所以看着还是闪。
     - 现在的做法（_tntToBlock / _blockToTnt / _fzBlockTick）：
         · 被冻住的 TNT 不再“按住”，而是直接换成一格 minecraft:tnt 方块：
             _putBlock(那一格, {"name": "minecraft:tnt"}) → 读回来确认成功
             → 才 DestroyEntity(原来那坨)。
           方块天生不会闪、不冒烟、没有引信，看上去就是彻底定住了。
         · 那一格要是被别的东西占着（不是空气），或者放了之后读回来不是 TNT
           （区域没加载 / 被保护 / 版本不给放），就放弃换方块、退回老办法
           （把它按住 + 定时换新的），不会把东西弄丢。
         · 记账放在 _fzBlock，键是 (x, y, z, 维度)，内容 {blk, pos, rot, dim, type}。
           注意 pos 存的是【原来那坨 TNT 的脚底坐标】，还回去的时候照它生成。
         · _fzBlockTick 每 tick 跑一次（_fzBlock 空就直接返回，几乎不花钱）：
             还在被「开着静止」的玩家罩着（_blkCovered：同维度 + 在
             FREEZE_RANGE 以内）→ 继续冻着；没人罩了 → 还回去。
             另外每 tick 都读一次那格：已经不是 TNT 方块了（被玩家挖掉 / 换掉），
             就把记账丢掉 —— 免得凭空又多冒出一坨点着的 TNT。
         · 「还回去」= 把那格设成空气 + 用记录里的脚底坐标、朝向重新生成一坨
           minecraft:tnt（引信是满的），交给游戏自己接着炸。
           注意只有那格仍然是 TNT 方块才会动手，玩家自己在那里放了别的东西
           就不会被误删。
         · _fzBlockTick 的调用点放在 _freezeTick 里【药效判定之后】，
           所以在“开关关掉 / 药效到点 / 玩家掉线”这些路径上一样会跑；
           _freezeReleaseAll 故意【不碰】_fzBlock —— 因为它在“身边没实体”那条
           分支也会被调用，而那种时候玩家可能还站在原地罩着这一格，
           一碰就会变成「还回去 → 下一 tick 又被冻上」的来回折腾。
     - 什么情况会漏（已知限制）：如果在静止期间整个服务器被强杀 / 崩溃，
       存档里会留下一格 TNT 方块（正常退出世界、掉线、切维度都会自动还回去）。

   · 静止期间「TNT 炸不起来」是怎么做的（第十九次修改）
     - 先说做不到的那部分：引信没有任何接口能暂停 —— 官方文档里搜
       “引信 / fuse”是零结果，能写 NBT 的接口（SetEntityNBTTags）也不存在。
       所以只能绕开，不能真的给它按暂停键。
     - 主路 _tntTick / _refreshBoom：
         · 被冻住的爆炸物记在 _fzBoom（id -> {n, pos, rot, dim, type}）；
         · 每 tick 计数器 +1，到了 freezeTntTicks()（默认 40 tick = 2 秒）就
             CreateEngineEntityByTypeStr(同类型, 原位置, 原朝向, 同维度)
             → 造出来了才 DestroyEntity(旧的)
             → 记账整个挪到新 id 上，并把新的一坨按进 _fzHold 继续钉住。
           顺序很关键：先造后删。造不出来就留着旧的，宁可引信继续走，
           也不能让它凭空消失。
         · 新的一坨引信是默认的 4 秒，而每 2 秒就换一次，所以永远到不了爆炸。
         · 只对抛射物那类的爆炸物换（TNT）。苦力怕是生物，
           AI 被 SetBlockControlAi(False) 屏蔽之后就不会自爆，不用换。
     - 换完之后要做的两件小事：
         · _fzNear.clear() —— 下一 tick 重新找一圈，否则新 id 还没被
           “谁在附近”扫到，会被当成“跑出范围”解冻掉，那就白换了；
         · _fzKeep（FREEZE_TNT_KEEP_SECONDS，默认 0.5 秒）—— 刚换出来的
           这一小段时间里，就算没被扫到也不解冻（_keepAlive 管这个）。
     - 兜底 _stopBlast（在 OnExplode 里，事件一进来就做）：
         · 认领 _isFrozenBlast：sourceId 在 _fzBoom / _fzHold / _fzAi 里，
           或者 explodePos 离某个被冻住的爆炸物 ≤ FREEZE_BLAST_RADIUS
           （默认 2 格）。为什么不能只认 sourceId —— 有的版本里这个 id
           给的是“点火的人”，不是那坨 TNT。
         · 方块：把 args["blocks"] 每一项的 b[3] 设成 True。
           官方原话：“通过设置 blocks 中 cancel 的 bool 值为 True
           可以将该方块的爆炸取消”。
         · 人：victims 先 _shieldVictims 护住，再 del victims[:] 试着清空
           （清不掉也没关系，护住 + 补血顶得住）。
         · 这一段必须放在「身上有没有回溯药水」的判断【之前】，
           不然只喝了静止药水、没喝回溯药水的玩家挡不住爆炸。
         · 方块被取消之后不会被记进 _blocks（记录循环本来就跳过 cancel 的），
           所以“回溯”那条线完全不受影响（有回归测试盯着这一点）。
     - _fzGuardTick（每 tick 跑一次，两个字典平时都是空的，等于什么都不做）：
         · _fzImmune 到点 → ImmuneDamage(False) 撤回；
         · _fzHeal 到点 → 血量比记下来的少就补回去。
     - 为什么用 ImmuneDamage：文档里唯一一个“让实体免疫伤害”的接口
       （CreateHurt 组件 → ImmuneDamage(bool)）。但它写的是【存档属性】，
       所以掉线（DelServerPlayerEvent）和死亡（PlayerDieEvent）都会立刻撤回一次，
       绝不把谁留成永久无敌。
